## 夹具与 API 评估

已对照当前源码检查现有控制器 activation/end/close 辅助方法、构造签名、Iap2Messages 构建器及偏好设置写入方法。模拟输出边界在构造控制器之前安装；token 从获批钩子捕获，从不伪造。反射仅限于控制器锁观察和路线状态／锁检查，不涉及私有 token 身份或所有权修改。

受控歌曲调度器记录实际立即任务／计时器接受情况，保持就绪任务 FIFO，并使用单个异步写入线程。捕获的计时器体即使取消后仍可运行，以测试实际过期拒绝。模拟命令边界通过实际写入／清理逻辑返回合成成功结果；不声称验证了厂商响应解析。现有解析器回归仍为必需。回调错误被收集并在测试线程抛出，因此生产 runCatching 不能默默将失败观察变成通过。

清理过程释放屏障，等待有界辅助工作结束，关闭真实控制器／会话，在模拟端口仍安装时排空任务，取消计时器，仅终止测试执行器，然后重置单例环境并恢复完整偏好设置值和流控制。若测试拥有的执行器不能进入静止状态，拒绝恢复真实端口。构造失败也会调用清理。显式检查规范重置及有效独立运行行为；冻结的既有 note/timer 测试保持不变，仍需按要求运行。
