## 独立状态修改与锁审计

**令牌顺序。** retire 仅在 mutationLock 下写入 AtomicBoolean；withAdmittedMutation 在同一私有监视器下检查同一个标志并调用本地闭包。isAdmitted 保持非阻塞原子读取。顺序执行的运行用例证明了两种明确顺序以及持有防护锁时的观测。源码检查证明了互斥关系；这里不声称已通过强制同时竞争的运行实验予以证明。

**调用关系图。** 既有控制器 activation/end 在 retire 前取得控制器生命周期锁；close 还持有 wirelessResourceLock。未改动的 call end 和工作器替换会在 retire 前取得各自的监视器。新的导航防护路径采用 navigation -> token -> overlay 或 song。直接歌曲路径在 state 下捕获状态，释放它，再进入 token -> song state。没有受防护闭包取得 controller/call/worker/navigation 锁，也没有把 overlay 与 song 锁嵌套。导航工作器 start/submit/clear 在 token/本地状态锁释放后执行，仅处于导航所有权保护下。它们使用未改动的有界异步工作器；桥接回调不会在提交线程内联执行。

**导航提交。** Start 在受保护工作之外解析 context/availability，在已审查的锁顺序内提交 owner/epoch、歌曲上下文/所有权和待发布内容，然后无锁调用 start 钩子。每次工作器启动前最终检查精确 owner/epoch/admission，从而修复 #93。路由输入执行初始和最终检查，在防护内调用一次未改动的解析器，并在同一本地临界区提交其待发布内容。歌曲输入传递生产者身份。显式 null 帧无法认领已拥有或仍存储着已退役所有者的会话。

监听器变更、当前所有者刷新、发布选择和终止清理保留各自独立的管理用途。待发布内容携带 epoch、监听器身份/代次以及 revision。监听器调用和 handler 投递在锁外执行。#95 中已消耗的退役回调只释放其精确 ticket/candidate 调度槽位；既不交付 A，也不修改 route/shown 状态，且不能清除替代者的槽位。回归测试在这一精确顺序后执行有效的 B 和终止两个后继路径。

**歌曲提交。** ownerStarted 仅针对新的导航 owner/epoch 重置旧元数据和定时器意图，同时保留带身份标记的物理已显示记录，使同文本 B 无法继承 A 的输出身份。帧、设置、提示、过期、入队准入、命令准入和成功完成均通过 mutate 使用捕获的 owner/epoch。在入口和完成时重新检查目标卡片/revision。偏好读取发生在受防护提交前；调度器、shell/结果边界和日志发生在锁释放后。旧定时器签名及字段类型保持可用。无所有者的 shown 相等判断允许合法的独立模式去重；每次完成仍须满足其精确生命周期。

ownerEnded 创建本地终止意图并返回不可变的捕获入队闭包。导航在释放自身锁后调用该闭包；所有者转换内部不调用调度器。独立模式 end 在歌曲状态锁之外执行退役，重新检查捕获的 epoch，并使旧定时器失效。终止阶段的无所有者 epoch 防止陈旧清除/完成影响 B。

**已进入的工作与队列。** 捕获的包装任务可能在退役后竞争进入异步队列，但任务入口会拒绝陈旧所有权。已获准进入的外部操作可以完成；完成回调不能恢复陈旧的本地状态。测试衡量契约指定的调度情形，并借助夹具屏障（#94）稳定工作器任务计数；不声称普遍实现物理取消，也不声称跨 queue.clear 保持历史累计队列计数。

**辅助路径 #96 的限制。** End 在终止 owner epoch 的同时捕获不可变 endedToken，然后在无锁准入后仅携带该非 null 身份调用旧 call 边界。后续无法采用可变 lastEndedToken 或 null 表示当前所有者的语义。map 令牌 setter 仍是经源码审计的普通 volatile 赋值。新夹具有意使用假的 call/map 辅助效果；因此 #96 及这些未改动内部实现有源码审查证据，尚无新增直接辅助路径运行证明。已获准进入的辅助效果保留已批准的限制。
