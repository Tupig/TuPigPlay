## 退役、所有权与锁审计

令牌类对 `retire` 和准入检查加闭包使用同一私有 `mutationLock`；`isAdmitted` 保持原子非阻塞读取。退役不调用回调。防护及其锁观测 API 既不暴露监视器，也不暴露凭据材料。

既有控制器 replacement/end/close 调用方在控制器生命周期锁下取得退役锁，close 还处于无线资源所有权保护下。冻结的导航工作器可以在其工作器监视器下执行退役；冻结的 call 子系统可以在其生命周期监视器下执行退役。配套 HUD 路径没有引入在持有令牌防护锁时反向进入这些监视器的锁边。

导航在生命周期所有权保护下管理 start/end 和路由发布转换。Start 在加锁前计算应用上下文/可用性，以普通赋值提交已解析的歌曲上下文，然后调用本地歌曲转换。歌曲与 overlay 状态锁在不同临界区分别取得。锁外 start 钩子位于最终 owner/epoch/admission 检查和真实工作器入队之前，所以延迟 A 无法在 B 之后触发工作器替换（#93）。Map 令牌赋值是导航所有权保护下、token/state 释放后的叶级 setter；map 初始化和 call 关联在准入检查后于受保护锁外执行。

路由输入捕获显式生产者身份，并在无锁钩子之后重新检查它。对于获准所有权，真实解码器在 navigation → token → overlay 内运行一次。被拒绝的生产者路径不修改解码器/意图状态。仍被存储的退役所有者不能允许 null 生产者进入。有效 NONE/重复帧保留未改动解码器的隐藏新鲜度/宽限期行为。路由监听器和 Handler.post 在受保护锁外执行；待发布内容携带本地 epoch、监听器代次、revision 和令牌身份。终止发布使用自身无所有者的终止 epoch，而不是通过已退役令牌的正常准入。

Navigation → worker 入队仅发生在 token/state 释放之后。工作器和夹具执行器保持异步，不使用 CallerRunsPolicy。桥接操作期间，回调线程本身不持有 navigation/token/state/worker 准入锁。这并不保证另一个线程开始回调前，提交线程的每一把锁都已释放；保留的编码前勘误已对此说明。

直接歌曲操作在 state 下捕获 owner/epoch，释放 state，然后取得 token → state 并重新检查。共用的 `mutate` 辅助函数防止退役赢得竞争后再次进行有所有者的本地提交。本地 owner start/end 和独立终止转换仅操作 state，并由导航或精确捕获的所有者排序。持有歌曲 state 时，不会发生 song → navigation/token 的锁获取。

歌曲生产者输入接收显式令牌，包括在退役所有者仍被存储时拒绝 null。B 转换清除 A 的解码器元数据、wanted 值、notes/change 意图及 announcement 状态。保留最后完成的物理 shown 记录不会填充 B 元数据：有所有者的去重要求同一 owner 和 epoch。无所有者的相等规则仍仅限于 null shownOwner，从而保留冻结的旧 timer/note 夹具行为。

每个歌曲操作携带不可变 owner、epoch、revision、card 和 context。队列准入、物理入口和成功完成都会重新验证这些值；定时器还要求精确匹配其存储对象身份。偏好、执行器提交、定时器调度、命令执行和固定日志都在 token/state 锁外。先前获准的命令可以完成；被拒绝的完成不能改变 shown/stamps/firstLogged，也不能将后续工作入队。捕获的分发操作可能在实际入队前与退役竞争，但其包装器在执行时会拒绝；源码和契约不声称能物理取消，也不声称所有情况下陈旧队列条目都为零。

## 测试边界与清理审查

唯一新增测试使用真实控制器 activation/end/close、真实导航工作器，以及带合成外部结果的实际歌曲定时器/写入/完成逻辑。控制器身份通过无锁 start 钩子捕获；控制器反射仅读取锁对象以观测当前线程，不读取私有令牌所有权。路由反射观测未改动的解析器状态。帧/业务值均为合成值。

导航和歌曲假环境在构造控制器之前安装，覆盖无令牌引导阶段。实际工作器执行器使用标准有界单线程 ThreadPoolExecutor 和 AbortPolicy。受控歌曲调度器从不内联执行，获准任务数有界，并使用一个实际线程；已进入 A 的测试不会在线程阻塞期间伪造 B shown 状态。回调断言被保留，并在生产 runCatching 之外呈现。

Teardown 在假端口仍安装时释放屏障、等待自有 future、关闭控制器和会话、等待控制器拆除、取消后续定时器，并排空工作/main-handler 回调。然后仅终止测试自有执行器。所有自有执行器终止后才恢复真实端口，否则 teardown 失败。Reset 清除旧有和新增 route/song/ownership/timer/publication/stamp/counter 字段，恢复保存的 context/handler/clock 与流控制/偏好状态，不关闭生产执行器。

冻结的 BydClusterSongNoteTest 和 BydClusterSongTimerTest 保留所需字段名及 `endNote(Context, Any)` / `endChange(Context, Any)` 包装器。它们合法的无所有者反射 shown 值仍通过 null shownOwner 规则抑制输出；有所有者的同文本 B 必须发出自己的命令。未改动套件成功执行和最终完全静止仍是运行时义务，不是本次源码审查的结论。
